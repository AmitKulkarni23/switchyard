# UI Brief v2: describe / upload → review → Railway vs AWS

Shaped via `/impeccable shape` on 2026-11-01. Visual world unchanged: **Ratings Chart** (`ui-brief.md`). Layout chosen in the surface round: **Split Workspace** (`.impeccable/mocks/decision/surface-split.html`). Mode: Operate. Flow and backend: `design-path.md`.

1. **Job and audience**: planners (engineers and founders before they build) describe an idea; this is the primary path. Operators drop an AWS bill, a CloudFormation template, or Railway `config pull` / `usage` JSON. Railway sales staff use the same screens on calls.
2. **Outcome and proof**: within five seconds of results, "Railway $A–$B vs AWS $C–$D per month" side by side and which costs less. Proof: expandable per-part math; for ideas, each part's quoted "why" and model agreement (4/4, 3/4); every assumption visible and editable. No invented claims.
3. **Layout: Split Workspace**
   - **Entry** (before anything is priced): "What are you building?" as a large ruled text box with three optional fields (users, requests a day, data size) and **Price it**. Below a rule: **Already running something? Drop a file**, listing AWS bill (PDF/CSV), CloudFormation (YAML/JSON), Railway `config pull` and/or `usage` JSON with both commands copyable. Privacy per path: text goes to four models via OpenRouter; files never go to an LLM and are deleted after parsing.
   - **Workspace** (after the first pricing): left panel (~40%, washed ground, ruled) is *what you told us*: the idea text or file chip(s), up to three multiple-choice questions, the assumptions (traffic shape segmented: steady / business hours / spiky / mostly idle; requests a day; data GB; egress), and the parts list with size selects, quoted "why", agreement counts, and 2-of-4 suggestions unticked. Right panel (~60%) is the live comparison: verdict band (Railway range | AWS range | difference naming the cheaper side), then the per-part table with what each provider uses and its monthly cost. Every edit on the left reprices the right in the browser.
   - **Review only when usage is missing**: ideas, CloudFormation and Railway structure-only open the workspace with the left panel's questions expanded and highlighted. Bills and Railway usage files open it with the left panel collapsed to a summary ("15 parts from your bill · Edit").
   - **Billed side**: for an AWS bill or Railway usage, that column reads "today (billed)" with one exact number. The busy slider appears only where usage is assumed.
   - AWS-only overhead (NAT gateway, load balancer) appears as rows with Railway $0. Lambda vs containers: the AWS cell shows the cheaper option; expanding shows both and the crossover.
   - Masthead: source, Export PDF, Share link.
4. **Scope and anti-goals**: entry, waiting state, workspace, error and fallback states. No chat UI, no raw model prose, no hidden disagreement, no fake precision, no Railway-marketing look, never bury where AWS wins.
5. **States and ranges**: entry empty; idea too short (inline hint "Add who uses it and what it does"); one or two Railway files recognised ("Structure ✓ · Usage —"). Waiting: one progress line, ~10–20 s, Cancel. "3 of 4 models answered". Panel failure or no API key → starter-design picker landing in the same workspace. 1 to 30+ parts; unmapped CloudFormation resources listed as not priced. Results where AWS is cheaper, Railway is cheaper, or the ranges overlap, shown equally plainly.
6. **Interaction and responsive**: share link `/?e=<id>` restores the whole workspace. Below 1100px the panels stack: comparison first, then a sticky "Edit what you told us" bar that opens the left panel; each part becomes stacked Railway then AWS rows, no cards.
7. **Constraints and open decisions**: WCAG AA; standard MUI controls re-themed. `PRODUCT.md` predates this scope and should be refreshed with `/impeccable init`. `DESIGN.md` comes from the finish review of the current build (needs Playwright approval). Model spend cap and rate limit undecided.
